# 滞留改动登记册（格式样例）

> 本文件是 `add-stalled-change-triage` 交付的登记册格式样例（本地产物），展示 apply step 8 分诊与归档技能登记所用记录结构。实际登记册由 apply / 归档技能在 `openspec/changes/<提案名>/滞留改动登记.md` 创建与追加。

## 记录结构（六字段，缺一不可）

每条记录必须包含以下六个字段；任一字段无法确定时，填入显式占位说明（如「待定：归属非本提案作者」）而非留空或省略字段：

| 字段 | 含义 |
|------|------|
| 日期 | 登记当天日期（YYYY-MM-DD） |
| 路径 | 滞留改动的工作区相对路径 |
| 归属 | 该改动属于谁/哪个提案/哪类工作（无法确定时写占位说明） |
| 滞留原因 | 为何未随本轮提交（如「无关改动不入本提案 commit」「用户拒绝提交」） |
| 建议处置 | 给后续会话或所有者的建议（如「并入其所属提案的下一轮 apply」） |
| 状态 | open / resolved / escalated_to_human 等；状态变化以追加新记录表达 |

## 追加式纪律

- 新记录只追加在文件末尾；既有记录行**永不删除或改写**。
- 状态变化 = 追加一条新记录，回指原记录（引用其日期与路径），使完整滞留历史随时可还原。
- 本样例中的记录均为演示内容，不对应真实工作区状态。
